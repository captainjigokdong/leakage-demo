# 7단계 분석 계획 (정답표 복호화 전 고정, 2026-10-03)

이 파일은 정답표를 열기 전, 보고서 본문과 탐지 결과를 보지 않은 상태에서 커밋한다.
여기 적힌 분석은 **미리 정한 분석**이다. 여기 없는 분석을 결과를 본 뒤 추가하면 보고서에 **"사후 분석"**으로 표시해 구분한다.

근거: `docs/success_criteria.md`(H1·H2, 잠김), `docs/phases.md` 6·7단계 결정, 2026-10-03 사용자 지시(7단계 계획 승인 시 1~6번).

## 1. 순서 규칙

1. 정답표는 암호를 환경 변수로 받아 메모리에서만 복호화한다. 평문은 파일로 쓰지 않는다.
2. 변형 파일 SHA-256을 정답표·`docs/injection_log.md`와 대조한다. 어긋나면 멈춘다.
3. 잠긴 채점기(`experiment/grader.py`)로 맹검 채점 → 요약. **채점 결과(grades, summary)를 먼저 커밋한다.**
4. 그다음에야 놓친 사례의 보고서 본문을 읽는다. **읽은 뒤에 채점 결과를 바꾸지 않는다.** 채점기 버그로 보이는 것은 `docs/known_issues.md`에 적기만 한다.

## 2. 미리 정한 채점 분석

세 가지 분석 묶음을 같은 지표로 계산한다.

| 이름 | 보고서 | 빈칸 행 | 지위 |
|---|---|---|---|
| **주 분석** | 채택된 실행 119개 | 분모에서 뺌 | H1·H2 판정 |
| **첫 시도 분석** | 행마다 첫 시도 120개 (`experiment/runs/first_attempt_reports/`) | 없음 (첫 시도는 모두 있음) | 주 분석과 같은 무게로 보고 |
| **빈칸 = 미탐지 분석** | 채택된 119개 + 빈칸 1행을 "지적 0개" 보고서로 | 미탐지 (오경보 0) | 함께 보고 |

빈칸 = 미탐지 분석은 빈칸 행을 `findings` 블록이 있는 빈 목록 보고서로 만들어 같은 채점기에 넣는다 (그 결과 모든 배치 미탐지, 오경보 0).

각 묶음에서 계산하는 것 (채점기 `summarize` 출력 그대로):
- 탐지율: 전체 / 공개 / 보류 6개 / 조정하지 않은 보류 3개, 질문(Q)별, 주 분석(항목)·보조 분석(항목 + 종류)
- H1: 변형 단위 짝지은 부트스트랩 95% 신뢰구간 하한 > 0, 그리고 깨끗한 변형에서 (가) 오경보 보고서당 평균 ≤ 1
- H2: (가)의 보류 탐지율 > 무작위 기대치. **(나)의 보류 탐지율과 그 기대치를 함께**, 보류 6개 전체와 조정 안 한 3개 따로
- 오경보: 깨끗한·결함 변형 각각, 두 조건
- 종류 불명, 점검 불가, 대상 불명, 형식 오류, 추가 판정 개수 (조건별)
- 반복 간 안정성
- **점검기만으로 본 탐지율**(2차 지표): (가) 점검기 출력 59개, 보류 탐지율 포함. H2 표에도 함께 적는다.

보고 형식 (사용자 지시):
- 보고서 맨 앞에 세 분석 묶음의 H1·H2 결과를 한 표로 나란히 둔다. 기준을 통과하지 못한 것은 그대로 적는다.
- 보조 분석 수치 옆에 "핵심어 사전이 점검기 표현을 더 잘 인식해 (가)에 유리할 수 있다"는 한계와 조건별 종류 불명 개수를 적는다.
- 주·보조 분석 결론이 다르면 보조를 함께 제시하고 조심해서 해석한다 (판정은 주 분석).

## 3. 미리 정한 참고 분석 (6단계 결정)

- (가)를 `checker_invoked` 참/거짓으로 나눈 탐지율, 부르지 않은 실행 중 권한 거부가 있었던 수(`no_checker_after_denial`).
- 조건별 폐기 수와 사유(전체 탐색, 자기 폴더 안 `..`), 설계서별 폐기 분포 (`results/discards.json`의 `by_variant`).
- 폐기된 시도 중 실제로 실행된 걸린 호출 수와, 그중 자기 실행 폴더 밖에 닿은 것(6단계 확인: 2건, 둘 다 (가)·경로 이름만).
- 놓친 사례 분석: 미탐지 배치를 조건별로 정리. 4단계에서 조정한 보류 3개는 조정이 탐지에 영향을 주었는지 따로 적는다.

## 4. 누수 효과 시연 (`experiment/leakage_effect.py`, 보조 분석)

### 4.1 쓸 누수 목록 (실행 전 고정)

공개 오류 목록(`designs/error_catalog_public.csv`)에서만 고른다 (보류 목록은 쓰지 않는다). 각 누수는 기본 설계서(`designs/base/*.json`)에 **하나만** 넣은 설계와, 그 유형의 누수를 **모두** 넣은 설계를 만든다. 수정 설계 = 기본 설계서(점검기 통과).

**고정 시점 (30일 재입원, `fixed_readmission`)**

| id | 공개 목록 | 넣는 방법 | Q |
|---|---|---|---|
| F1 | E12 | 특징 `next_unit`: admissions, scope `next_admission`, column `unit`, agg `value` (결과를 정한 다음 입원 행의 변수) | Q4 |
| F2 | E06 | 분할을 입원 단위로: `split.key = admission_id`, `split_unit`은 family 그대로 | Q2 |
| F3 | E08 | 중앙값 대치 `fit_scope = all` | Q3 |
| F4 | E10 | 단변량 연관 상위 k개 특징 선택(k = 특징 열 수의 절반, 올림)을 전체 데이터로 적합 (`kind: select`, `fit_scope: all`) | Q3 |

**동적 AKI (48시간 AKI, `dynamic_aki`)**

| id | 공개 목록 | 넣는 방법 | Q |
|---|---|---|---|
| D1 | E01 | 특징 `dx_aki`: diagnoses, filter `icd_code` N17, scope `index_admission`, agg `any` (이번 입원 진단 코드) | Q1 |
| D2 | E03 | 특징 `cr_max_adm`: labs creatinine, `report_time`, 창 admit ~ discharge, agg `max` | Q1 |
| D3 | (분할) | 행(예측 시점) 단위 분할: `split.method = random_rows` | Q2 |
| D4 | E08 | 중앙값 대치 `fit_scope = all` | Q3 |
| D5 | E10 | 위 F4와 같은 특징 선택을 전체 데이터로 적합 | Q3 |
| D6 | E13 | 특징 `renal_order`: orders `dialysis_order`·`nephrology_consult`, 창 admit ~ tₚ, agg `any` (결과 대리 변수, 점검기 판정 "경고") | Q4 |

쓰지 않는 것과 이유: E14·E15(포함 기준)는 코호트 자체를 바꿔 같은 시험 집합에서 AUROC를 비교할 수 없다. E02(시간 기준 열 변경)는 D2와 같은 Q1 시간 누수라 겹쳐서 뺀다. E07·E17은 각각 F2/D3, 결과 확인 강도 문제로 AUROC 비교의 대상이 아니다.

설계서 형식으로 표현할 수 없는 누수가 있으면 실행 전에 이 표를 고치지 않고, 보고서에 "형식으로 표현 못 함"으로 적고 뺀다.

### 4.2 평가 방법

- 특징은 `leakcheck.features.make_feature`(출처 기록 함수)로만 만든다. 결과는 `leakcheck.outcomes.label`, 분할은 `leakcheck.splitting.assign`.
- **시험 집합**: 수정 설계의 분할(가족 단위, `test_fraction` 0.3)이 정한 시험 집합을 기준으로 한다. 분할 누수(F2, D3)는 학습·시험이 그 누수 분할로 바뀐다.
- 모든 설계(누수 포함)는 결정 카드 → 승인 → 잠금을 거친 뒤에만 `leakcheck.lock.auroc`로 AUROC를 계산한다.
- 모델: 로지스틱 회귀, HistGradientBoosting, TPOT 1.1.0.
- **시드 변동**: 로지스틱 회귀·부스팅은 분할 시드 5개(20261002 기본 + 1~4 더함)로 반복해 평균과 범위(최소~최대)를 낸다. 부스팅은 모델 시드도 같은 값으로 바꾼다. TPOT는 기본 시드 1개만 (시간 제한).
- **TPOT**: 실행당 약 5분 제한, 작은 세대·개체 수. 내부 교차검증 분할 단위를 소스와 실행으로 확인한다. 그룹 분할을 직접 받지 못하면 환자(가족) 단위로 미리 나눈 폴드를 넘기고, 그 과정을 보고서에 적는다. TPOT는 수정 설계와 "모두 넣은" 설계에만 돌린다 (시간 예산 약 20분).
- 해석은 절대값이 아니라 **누수 유무에 따른 AUROC 차이**로 한다 (합성 데이터 AUROC는 임상적 의미가 없다).
