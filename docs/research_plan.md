# 연구 계획 (데모용 요약)

출처: 프로젝트 문서 「연구계획 v3 — 범위 확정과 작동 예시」(2026.09.30) + 2026.10.02 대화에서 확정한 변경 사항. 데모에 필요한 것만 추렸다.

## 1. 한 문장

표 형식 임상 데이터를 분석하는 에이전트가 분석 **전에** 설계를 스스로 점검하게 만들고, 맹검으로 심은 결함을 스킬 유무에 따라 얼마나 잡는지 측정한다.

**범위**: 예측 연구만. 인과 연구(교란 보정)는 범위 밖. 데모는 EHR형 합성 데이터와 두 설계 유형만 다룬다.

## 2. 일곱 가지 질문과 판정 수준

| 질문 | 정의 | 판정 수준 | 데모에서 |
|---|---|---|---|
| **Q1 가용 시점** | 모든 정보가 예측 시점 tₚ에 실제로 알려져 있었는가 | 강함 | 차단 |
| **Q2 독립 단위** | 학습·평가가 서로 독립인 단위(환자, 가족)로 나뉘었는가 | 강함 | 차단 |
| **Q3 적합 범위** | 데이터에서 추정한 모든 것(대치, 표준화, 특징 선택)이 학습 부분에서만 추정되었는가 | 강함 | 차단 |
| **Q5 선택 시점** | 누가 포함되는지가 기준 시점 이전 정보로만 정해졌는가 | 중간 | 차단 |
| **Q6 다중 시도** | 몇 번 시도했고 그만큼 보정했는가 | 중간 | 기록만 |
| **Q4 결과 출처** | 결과를 정의한 정보(또는 그 대리 변수)가 입력에 섞이지 않았는가 | 약함 | 같은 행/결과 창 재사용은 차단, 대리 변수 목록 일치는 경고 |
| **Q7 결과 확인 균질성** | 결과가 모든 집단에서 같은 강도로 확인되었는가 | 약함 | 경고만 |

강함은 **조건부**다: 꼬리표 규칙이 옳고 출처 추적이 완전할 때만 성립한다.

판정은 세 가지: **[차단]** 설계를 되돌림 · **[경고]** 사람이 확인 · **[통과]** 기록만.

## 3. 꼬리표 네 개 (행마다)

| 꼬리표 | 뜻 | 예 |
|---|---|---|
| entity (개체) | 이 값이 누구의 것인가 | P001 |
| split_unit (독립 단위) | 분할할 때 함께 움직여야 하는 묶음. **연구 질문이 정함** (기본값은 환자, 설계서에서 덮어씀) | P001, 가족 F12 |
| available_time (확인 가능 시각) | 이 값이 **알려진** 가장 이른 시각 (생긴 시각이 아님) | 크레아티닌 → 보고 시각 |
| provenance (출처) | 원본 테이블·행 ID, 계산 방식, 적합에 쓰인 데이터 범위 | labs#8812 |

**파생 특징은 꼬리표를 물려받는다**: available_time = 재료 행들의 최댓값, provenance = 재료 행 목록 + 계산 방식(+ 적합 범위).

## 4. 규칙표 (어댑터)

사람이 정하고 잠근 규칙을 모든 행에 기계적으로 적용한다. 의미를 해석하지 않는다.

| 층 | 내용 | 예 |
|---|---|---|
| 1층 구조 | 데이터 구조만으로 정해짐 | patient_id 열 → entity, report_time 열 → available_time |
| 2층 맥락 | 데이터 밖의 지식 필요. 사람이 근거와 함께 적고 잠금 | 진단 코드 available_time = 퇴원 시각 (근거: MIMIC-IV diagnoses_icd 문서) |
| 3층 불확실 | 아무도 확실히 모름. 보수적 기본값 + 가정 기록 | 날짜만 있는 값 = 그날 23:59 |

규칙에 해당하지 않는 행, 모순(보고 시각 < 채취 시각)은 **추측하지 않고 멈춰서 보고**한다.

## 5. 결정 잠금

결과를 바꾸는 설계 결정(기준 크레아티닌 정의, 사망 처리, 제외 기준 등)은 **결정 카드**로 사람에게 보여 준다. 카드에는 기술 통계(표본 수, 결과율)만 있고 **모델 성능은 없다**. 승인 시 `locked=True`. 성능 계산 함수는 잠금 전 호출 시 예외를 던진다.

## 6. 데모의 두 설계 유형

| 유형 | 연구 질문 | tₚ | 단위 | 주요 함정 |
|---|---|---|---|---|
| 고정 시점 예측 | 퇴원 시 30일 내 재입원 | 퇴원 시각 | 입원 1건 = 1행 | 퇴원 후 정보(Q1), 결과가 섞인 변수(Q4) |
| 동적(랜드마크) 예측 | 입원 중 매일, 48시간 내 AKI (KDIGO 크레아티닌 기준) | 입원 후 24h, 48h, … 최대 7일 | 예측 시점 1개 = 1행 | tₚ 이후 정보(Q1), 한 환자 행 분할(Q2) |

**핵심 시연 예시**: "이번 입원 진단 코드 = 퇴원 시각에 확인 가능" 규칙 하나가
- 동적 예측(tₚ = 입원 중)에서는 available_time > tₚ → **차단**
- 고정 시점 예측(tₚ = 퇴원 시각)에서는 available_time ≤ tₚ → **통과**

규칙은 "언제 알려지는가"만 말하고, 쓸 수 있는지는 tₚ가 정한다. (참고: 실제 병원은 퇴원 후 코딩 지연이 있어 규칙을 "퇴원 + 지연"으로 바꾸면 재입원 예측에서도 차단된다. 규칙표 한 줄로 조정 가능하다는 점이 설계의 장점.)

## 7. 평가 설계 (2026.10.02 확정 사항 포함)

### 7.1 오류 목록
- Kapoor & Narayanan (2023) 누수 분류 8종과 PROBAST(+AI) 신호 질문에서 **구체적 오류 사례 18개**를 뽑는다.
- 각 사례는 하나의 질문(Q)에 대응. 권장 배분: Q1 4, Q2 3, Q3 3, Q4 3, Q5 3, Q7 2.

### 7.2 보류 (확정: 질문별 층화)
- 보류 단위는 질문(Q)이 아니라 **구체적 오류 사례**다. 스킬은 Q1~Q7 원리 전부에 대해 만든다.
- **질문별로 1개씩** 무작위 보류 (층화 추첨) → 6개 보류, 12개 공개.
- 목적: 스킬이 본 사례만 외운 것이 아니라 **원리를 점검하는지** 확인. 보류 사례를 잡으면 일반화의 증거, 못 잡으면 사례 암기 또는 규칙표 빈틈의 신호.
- 어떤 Q에도 맞지 않는 오류가 나오면 못 잡는 것이 정상이며 "틀의 한계"로 보고한다.

### 7.3 맹검 (확정: 18개 전체)
- 결함 주입은 **스크립트**가 무작위로 한다. 변형 파일 이름은 무의미한 코드(`design_A7F3.json`).
- "어느 파일에 무슨 오류"라는 정답표는 암호화해 봉인. 채점이 끝난 뒤에만 연다.
- 공개·보류 유형을 **섞어서 한꺼번에** 봉인한다 (보류 유형만 따로 두면 그 파일이 드러남).
- 혼자 하는 데모라 완전한 맹검은 아니다(공개 유형은 파일을 보면 알아챌 수 있음). 그래서 채점 규칙을 사전 고정하고 채점을 자동화한다.

### 7.4 실험 방식 (확정: 방식 A)
- 에이전트에게 **결함이 심어진 설계서 + 데이터**를 주고 "이 설계로 모델링을 준비하라. 진행 전에 설계에 문제가 있으면 보고하라"고 지시한다. 두 조건에 같은 지시.
- (가) 에이전트 + 점검 스킬 / (나) 같은 에이전트, 스킬 없음. 같은 모델, 같은 설정.
- 규모(제안): 설계 유형 2 × 변형 10(결함 8 + 깨끗한 것 2) × 조건 2 × 반복 3 = 120회.

### 7.5 채점 규칙 (실험 전 고정)
- **탐지**: 보고서가 결함이 있는 변수(또는 설정)를 지목하고 **문제 종류**(시점/분할/적합 범위/선택/결과 출처/확인 균질성)를 맞게 말한 경우.
- 지목만 하고 종류가 틀리거나 애매한 표현("이상할 수도")은 미탐지.
- 깨끗한 설계에서의 지적, 또는 결함 없는 항목에 대한 지적은 **오경보**.
- 채점은 조건(가/나)을 가린 상태로 자동화(규칙 + 별도 LLM 채점자, 채점 프롬프트 고정).

### 7.6 가설과 기준 (실험 전 고정)
| 가설 | 내용 | 기준 |
|---|---|---|
| **H1** | (가)는 (나)보다 탐지율이 높고, 깨끗한 설계에서 오경보는 설계당 평균 1건 이하 | 탐지율 차이 95% CI 하한 > 0, 오경보 평균 ≤ 1 |
| **H2** | (가)는 보류 사례도 잡는다 | 보류 사례 탐지율 > 같은 수의 경고를 무작위 배치했을 때의 기대 탐지율 |

### 7.7 지표
- 1차: 탐지율(공개 유형 / 보류 유형 따로, **질문별로 따로**), 오경보율
- 2차: 반복 간 안정성, 실행 시간

예상: Q1~Q3는 높고 Q4·Q7은 낮다. 그 결과 자체가 "에이전트 점검을 어디까지 자동화할 수 있는가"의 지도다.

### 7.8 누수 효과 시연 (보조 분석, 2026.10.02 추가)
- 주 결과는 탐지율이다. 모델 성능(AUROC)은 **누수가 성능을 부풀린다**는 것을 보여 주는 보조 시연에만 쓴다.
- 같은 합성 데이터로 누수 설계와 수정 설계를 각각 학습해 AUROC 차이를 본다. 모델은 로지스틱 회귀, 그래디언트 부스팅, TPOT(Moore 연구실의 AutoML, 1.x).
- 딥러닝은 쓰지 않는다. 표 형식 요약 특징이라 이점이 없고, 이 연구의 관심은 모델이 아니라 설계다.
- TPOT 내부 교차검증의 분할 단위를 확인한다. 반복 측정 데이터에서 행 단위 교차검증은 AutoML 자체의 Q2 누수다.
