**확정 사항 (2026-10-02 사용자 결정)**
- Q4 차단은 같은 테이블이라는 이유만으로 하지 않는다. 같은 행(테이블·필터·범위·시간 구간이 모두 겹침)이거나 특징의 창이 결과 창과 겹칠 때만 차단. 대리 변수 목록 일치는 결과와 같은 입원 범위일 때만 경고
- 시험에 "수상해 보이지만 정당한" 특징 추가: 이전 입원 진단 코드, 보고 시각으로 거른 검사(이번·이전 입원), tₚ 이전에 시작된 입원 수. 모두 통과
- Q2 데이터 단계: 선언 단위가 환자인데 같은 가족이 학습·평가에 나뉘면 경고
- Q7 기준: 하위 집단 측정 빈도 비 ≥ 2 → 경고. **고정값, 이후 변경 금지** (`rules.Q7_RATIO_THRESHOLD`)
- 출처 불명 특징은 경고 + "Q1~Q3 확인 불가"
- SKILL.md에는 공개 사례를 예시로 적지 않고 원리와 실행 방법만. 설계서 형식도 원리 기준(기호 시각, 범위, 적합 범위, 분할 키)

**결과 (2026-10-03)**: 시험 117개 통과 (`python -m pytest -q`, 약 20초). 공개 12개 사례 16개 조합(둘다 사례는 두 유형) 모두 설계서만으로, 그리고 데이터로도 기대 판정. 깨끗한 두 설계는 설계서 단계 통과, 데이터 단계에서는 Q2 가족 경고 하나만(독립 단위 = 환자). 5,000명 데이터 실행 시간: 동적 약 15초, 고정 약 3초. 결정 카드 결과율: 동적 AKI 48h 6.1%(예측 행 23,223), 30일 재입원 14.7%(입원 6,855).

**4단계로 넘길 것**: 깨끗한 기본 설계(독립 단위 = 환자)는 데이터 단계에서 Q2 가족 경고를 받는다. 이 데이터는 가족이 위험을 공유하도록 만들어졌으므로 원리상 맞는 경고다. 4단계 기본 설계에서 독립 단위를 가족으로 둘지(경고 없음), 환자로 두고 채점에서 이 경고를 오경보로 셀지 정해야 한다.

**주의**: 점검은 사례별 금지 목록이 아니라 **원리(시각 비교, 분할 키 비교, 적합 범위 비교)**로 구현한다. 보류 사례를 잡을 수 있는지가 여기에 달려 있다.

**확정 사항 (2026-10-03 사용자 결정, 실험 전 고정)**
- **오경보**: 결함을 심지 않은 항목(설계서의 특징·기준·분할·전처리·결과 설정)을 지적한 경우만 센다. 깨끗한 변형에서의 지적도 여기에 포함된다.
- **추가 판정은 오경보가 아니다**: 결함을 심은 항목에 정답표의 문제 종류 말고 다른 종류의 판정이 붙어도 오경보로 세지 않는다. 예: 한 특징에 가용 시점(Q1)과 결과 출처(Q4)가 같이 붙는 경우.
- **탐지 정의 두 가지를 모두 미리 고정한다.**
  - 주 분석: 결함을 심은 항목만 지목해도 탐지 (문제 종류 무관).
  - 보조 분석: 결함을 심은 항목을 지목하고, 정답표의 문제 종류(Q)도 맞혀야 탐지.
  - (2026-10-03 태그 전 변경: 처음에는 주·보조가 반대였다. 종류 판별이 (가)에 유리한 측정 편향을 만들어 바꿨다. 이유는 `docs/success_criteria.md`)
- (가)와 (나)에 **같은 규칙**을 적용한다.

**완료 기준**: 가짜 보고서 몇 개로 채점기가 의도대로 판정하는지 시험 (주 분석·보조 분석 각각, 추가 판정과 오경보 구분 포함)

**추가 결정 (2026-10-03 사용자 결정)**
- 지적 추출: 두 조건 공통 지시문에 보고서 끝 `findings` 목록(`target`, `problem`)을 요구하고 규칙 코드로 읽는다. 연구 계획 7.5의 "별도 LLM 채점자"는 쓰지 않는다 (CLAUDE.md 절대 규칙 7).
- 문제 종류: 지시문에 Q 분류를 알려 주지 않는다. `problem` 설명을 고정 핵심어 사전(점검기 표현 + 일반 표현, 한국어·영어)으로 Q에 대응시킨다. 대응되지 않으면 "종류 불명"(주 분석은 항목으로 판정, 보조 분석 미탐지), 조건별 개수 보고.
- "점검 불가" 지적: 탐지도 오경보도 아니고 개수만 보고. 해당 결함은 분모에 남고 미탐지.
- 경고 수준 지적도 탐지로 센다. 목록 밖 본문 서술은 채점하지 않는다 ("애매한 표현"의 정의).

  - **H2는 두 가지로 따로 보고한다**: (1) 보류 6개 전체, (2) 봉인 해제 뒤 조정하지 않은 보류 3개만. 4단계에서 보류 3개를 조정했기 때문이다 (조정 내용은 정답표 봉인본의 `holdout_adjusted`). 조정한 3개는 놓친 사례 분석에서 조정이 탐지에 영향을 주었는지 따로 적는다
  - 정답표를 연 뒤 각 변형 파일의 SHA-256을 정답표 봉인본의 값, `docs/injection_log.md`의 값과 대조한다
- [ ] **누수 효과 시연** (`experiment/leakage_effect.py`, 보조 분석): 두 설계 유형 각각에서 **누수 설계**(예: 퇴원 진단 코드 포함, 행 단위 분할, 전체 데이터 전처리)와 **점검 후 수정 설계**를 같은 데이터로 학습해 AUROC를 비교
  - 모델: 로지스틱 회귀, 그래디언트 부스팅(scikit-learn HistGradientBoosting), **TPOT** (`pip install TPOT`, 1.x)
  - TPOT는 세대 수·개체 수·시간 제한을 작게 잡는다 (실행당 수 분~십여 분)
  - **TPOT 내부 교차검증이 환자 단위 분할(GroupKFold 등)을 쓰는지 확인**한다. 동적 AKI 예측은 한 환자가 여러 행이라, 기본 행 단위 교차검증이면 TPOT 자체가 Q2 누수를 일으킨다. TPOT가 그룹 분할을 직접 받지 못하면 미리 환자 단위로 나눈 폴드를 넘기는 방식으로 우회하고, 그 과정을 보고서에 적는다
  - 수정 설계는 결정 잠금(`leakcheck/lock.py`)을 거친 뒤에만 성능을 계산한다
  - 결과는 절대값이 아니라 **누수 유무에 따른 차이**로 해석한다 (합성 데이터 AUROC는 임상적 의미 없음)
