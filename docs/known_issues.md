# 알려진 문제

`skill-frozen` 태그 뒤에 `leakcheck/`, `skill_src/`에서 발견한 버그는 고치지 않고 여기에 적는다 (CLAUDE.md 절대 규칙 3).
각 항목: 날짜, 발견 경위, 증상, 영향받는 질문(Q), 채점에 미치는 영향.

## 동결 전부터 알려진 한계 (2026-10-03)

- **기준 시점이 tₚ가 아닌 Q5**: `cohort.index_time`을 tₚ가 아닌 값(예: `admit`)으로 두면, 고정 시점 설계에서 입원 시각의 하한이 정해지지 않아(-∞) 기호 비교가 보수적으로 차단할 수 있다. 데모의 두 설계 유형은 기본값 tₚ를 쓴다.
- **창의 기준 열과 확인 가능 시각 열이 다를 때**: 두 열 사이 지연 상한이 규칙표에 없으면(검사 채취→보고 등) 창 끝이 tₚ보다 충분히 앞이어도 차단한다. 보수적 기본값(3층)이며 규칙표에 상한을 적으면 풀린다.
- **Q7 데이터 단계 후보 층**: 규칙표의 후보(병동, 성별)와 설계서의 `cohort.subgroups`만 본다. 다른 층의 확인 강도 차이는 보지 못한다.

## 4단계에서 확인한 한계 (2026-10-03)

- **외래 방문 테이블의 규칙 없음**: 4단계에 별도 파일로 추가한 `outpatient_visits`는 동결된 규칙표(`leakcheck/rules.py`)에 규칙이 없다.
  설계서가 이 테이블을 참조하면 점검기는 추측하지 않고 "규칙 없음"으로 멈춰 보고한다(의도된 동작).
  테이블을 데이터에 섞어 넣으면 꼬리표 단계 전체가 멈추므로 `synth.generate.load()`는 이 파일을 읽지 않는다.
  영향: 이 테이블을 쓰는 설계에서 Q1~Q7 판정 대신 "점검 불가"가 나온다. 채점에서 "점검 불가" 보고를 어떻게 셀지는 5단계 채점 규칙에서 정한다.
  → 5단계 결정(2026-10-03): "점검 불가" 지적은 탐지도 오경보도 아니고 개수만 따로 보고한다. 해당 결함은 분모에 남고 미탐지로 센다 (`experiment/scoring_rules.md` 3·5절).

## 7단계 채점 뒤 발견 (2026-10-03, 채점 결과 커밋 `4e76e7b` 뒤 — 채점 결과는 바꾸지 않음)

- **채점기의 "점검 불가" 핵심어가 일반 문장에 걸림** (`experiment/grader.py`, 잠김): `UNABLE`의 `"규칙이 없어"`, `"규칙이 없다"`가
  "결측 **처리 규칙이 없다**", "검열 **규칙이 없어**"처럼 설계서의 빈틈을 지적하는 문장에도 부분 문자열로 맞는다.
  그런 지적은 점검 불가로 분류되어 탐지도 오경보도 아니게 된다.
  - 발견 경위: 깨끗한 변형의 오경보 목록에서 `split.key` 지적이 빠진 이유를 확인하다 발견 (보고서 `49aa680fa20f`).
  - 영향 (주 분석, 사후 계산): 잘못 분류된 지적 (가) 8, (나) 12건, **모두 결함을 심지 않은 항목** → 탐지율 영향 없음.
    오경보가 적게 세어졌다. 바로잡으면 깨끗한 변형 보고서당 오경보 (가) 1.33 → 1.58, (나) 2.83 → 3.17,
    결함 변형 (가) 0.57 → 0.68, (나) 1.69 → 1.83. H1의 오경보 기준(≤ 1)은 바로잡기 전에도 이미 미달이고 바로잡으면 더 멀어진다.
  - 판정은 잠긴 채점기 결과 그대로 둔다.
- **보고서로 저장되는 것은 에이전트의 마지막 메시지뿐**: 일부 에이전트가 `findings` 목록을 작업 폴더의 보고서 파일(`REPORT.md` 등)에 쓰고,
  마지막 메시지에는 "보고서 끝에 붙였다"고만 적었다. 채점 규칙상 "목록 없음"(형식 오류)이고 그 보고서의 모든 결함이 미탐지가 된다.
  - 주 분석: (가) 3개 보고서·놓친 배치 4개, (나) 6개 보고서·놓친 배치 9개. 이 13개 배치는 모두 마지막 메시지 본문에 해당 항목 이름이 나온다 (문자열 검색, 사후 확인).
